# FidesOrigin 官网视觉设计进一步优化建议（R16 分析）

- **日期**：2026-09-30
- **基线**：main `3fc09cc`（含 R6–R15 全部视觉工作），基于线上实证截图（1920 超宽/横屏移动/组件特写）与令牌层源码分析
- **定位**：R6–R15 已解决"缺陷与一致性"，本报告聚焦**从"正确"到"卓越"的下一档提升**——均为锦上添花，非缺陷修复

---

## 总评

当前设计体系（Ledger Precision：深海军蓝 × 青铜金、衬线标题、hairline 分隔、令牌化动效）已达**机构级基准线**，工程一致性在同类站点前列。与世界一流（Stripe 工程信任感 / a16z crypto 前沿感 / 高盛研报排版纪律）的差距集中在五处：CJK 标题字体依赖系统回退、按钮缺少按压态、超宽屏内容档位、图片资产分辨率、以及部分微交互的物理感。

---

## 一、配色方案

### 现状评估 ✅ 良好
- 双主题令牌完备（ink/surface/gold/cream/steel + success/danger 功能色 + dim 变体）
- 对比度全量达标（R6 体检延续有效）
- 风险等级语义色（Cleared 绿 / Flagged 红）在 hero 面板正确使用

### 不足与改进
**C1｜低｜浅色主题下金色 hover 态层次单一**
- 浅色主题 hover 多为文字变色，缺少浅色下的"金雾"底色呼应（深色有 --fio-hover-wash）
- **改进**：浅色主题补一条 `--fio-hover-wash-light: rgba(122,98,54,0.06)`，按钮/链接 hover 时字色+底色双通道反馈
- **优先级**：P2

**C2｜低｜暖色系无中间过渡色阶**
- gold（#af915f）→ cream（#fce1b6）之间跨度大，渐变使用处（logo 文字、按钮面）已显色阶跳跃
- **改进**：增设 `--fio-gold-2: #c9ab76` 中间阶，渐变两端改用 gold→gold-2→cream 三段，金属光泽更细腻
- **优先级**：P3

## 二、字体与排版层级

### 现状评估 ✅ 结构良好
- 三栈完备（Fraunces 衬线 / Jakarta Sans 正文 / JetBrains Mono 数据），CJK 标题衬线已对齐英文气质（R11）

### 不足与改进
**T1｜高（本报告最高优先）｜CJK 标题依赖系统宋体，Windows 端质感不稳定**
- 当前栈 `Songti SC → STSong → SimSun → Noto Serif SC`：macOS 渲染精致，**Windows 回退到 SimSun（中易宋体）**——大字号下为点阵位图轮廓，笔锋毛糙，与 Fraunces 的细腻衬线质感落差明显
- **改进**：自托管 **Noto Serif SC / TC / JP 可变字重子集**（仅提取站点实际使用的 ~800 个 CJK 字形，约 300-400KB，woff2 分片 unicode-range），next/font local 接入，标题栈首位置入。收益：三平台标题质感完全一致
- **预期效果**：Windows 端中文标题从"系统宋体"升级为"设计级衬线"，与英文 Fraunces 气质真正拉平
- **优先级**：**P0**

**T2｜中｜Fraunces 未启用光学尺寸轴**
- Fraunces 是可变字体（opsz 轴），大标题应使用高对比 opsz=72+ 实例，正文级引用（如 Trust 引文 24px）应使用低对比 opsz=9-18
- **改进**：next/font 加载可变 Fraunces，标题类加 `font-variation-settings: "opsz" 72`；引文/副标类用 `"opsz" 18`
- **预期效果**：大标题衬线更锐利庄重（研报级），引文更耐读
- **优先级**：P1

**T3｜低｜数字表格未启用 tabular-nums**
- 合约地址表、对比表数字列未统一等宽数字特性
- **改进**：表格/指标带加 `font-variant-numeric: tabular-nums`
- **优先级**：P2

## 三、页面布局与留白

### 现状评估 ✅ 节奏统一
- 现代首页 7/9rem 交替节奏、legacy 120px section 统一、12 列栅格规范

### 不足与改进
**L1｜中｜超宽屏（≥1920）无更大容器档位**
- max-w-6xl（1152px）在 1920+ 视口下两侧留白达 384px+，hero 双栏内容显窄（实证截图确认：1920 下左右栏之间空隙过大）
- **改进**：新增 `2xl: max-w-7xl（1280px）` 容器档，hero 栅格在 2xl 下放宽；metrics 带同步
- **预期效果**：大屏用户获得"满而不挤"的机构级版面
- **优先级**：P1

**L2｜低｜hero 与 metrics 带之间的垂直留白在小高度屏偏大**
- 92svh hero + 下方留白，1366×768 笔记本下首屏信息密度偏低
- **改进**：hero 最小高度改 `min(92svh, 760px)` 上限约束，保证 768 高度屏首屏露出 metrics 带首行
- **优先级**：P2

## 四、按钮与交互动效

### 现状评估 ✅ 有体系
- hover 上浮/提亮、focus 金环、菜单 pop、reveal 预热，时长走令牌

### 不足与改进
**B1｜中｜全站无 :active 按压态（实测 0 处）**
- 所有按钮/链接只有 hover 与 focus 状态，鼠标按下瞬间无视觉反馈——世界级 UI（Stripe/Linear）的"按压下沉 1-2%"是质感细节
- **改进**：`.fio-btn:active, .btn:active { transform: translateY(1px); }`（主按钮可叠加 `scale(0.985)`），一条规则全站生效
- **预期效果**：点击获得物理确认感，消除"纸板按钮"感
- **优先级**：**P0（改动一行、收益立竿见影）**

**B2｜低｜hover 过渡全站统一 0.2s，主 CTA 可更快**
- 主按钮（金色面）hover 提亮用 0.2s，与文本链接同速——重量级元素宜更敏捷
- **改进**：主 CTA hover/active 过渡改 `--dur-1`（150ms）
- **优先级**：P3

**B3｜低｜卡片 hover 无位移响应**
- pricing 卡/博客卡 hover 仅边框/底色变化
- **改进**：卡片 hover 加 `translateY(-2px)` + 阴影加深（已有 --fio-shadow 令牌）
- **优先级**：P2

## 五、图片与图标质量

### 现状评估 ✅ 风格统一
- 图标全部内联 SVG 描边风（stroke 1.5-2），博客封面为品牌星点/刻线图形，logo 提供多规格 PNG

### 不足与改进
**I1｜中｜博客封面为位图 PNG，高密度屏发虚**
- covers/*.png（17-76KB）在 2x/3x 屏上文字与线条边缘发虚（实证：travel-rule 封面星点连线已现锯齿）
- **改进**：封面图重出 2x 分辨率版本或转 SVG（几何图形可完全矢量化为 SVG，<10KB）；`<img>` 加 `srcset` 1x/2x
- **优先级**：P1

**I2｜低｜OG 图为静态 PNG（139KB），可品牌化再设计**
- 当前 og-image.png 为通用深底 logo 图，未承载"技术图纸"母题（角标刻线/雷达/封印元素）
- **改进**：用 Satori/@vercel-og 构建期生成，复用 fio-ticks 角标 + 雷达纹 + 衬线标题版式
- **预期效果**：社交分享卡片与站内视觉语言完全同构
- **优先级**：P2

**I3｜低｜图片资源无现代格式**
- brand PNG 全部 PNG 格式（logo 127KB）
- **改进**：构建期加 webp/avif 副本 + `<picture>` 回退（下载按钮保留 PNG 原文件供品牌使用）
- **优先级**：P3

## 六、响应式适配

### 现状评估 ✅ 全档验证
- 320–1920 全档零溢出、横屏未裁切（实证 h1Bottom 268 < 375vh）、触控目标达标

### 不足与改进
**R1｜中｜平板竖屏（768-1024）hero 信息层级降档过激**
- md 断点下 hero 右侧面板（Live Screening）完全隐藏，仅剩标题+CTA——768 用户损失核心产品演示
- **改进**：md 区间将面板改为**折叠卡片**置于 CTA 下方（默认收起，点击展开），或缩略为单行状态条
- **优先级**：P2

**R2｜低｜横屏手机 hero 上下内边距偏大**
- 实测未裁切，但 py-28（112px）×2 占掉横屏 60% 高度
- **改进**：`@media (max-height: 480px)` 下 hero 改 py-16
- **优先级**：P3

## 七、品牌一致性

### 现状评估 ✅ 高度统一
- 母题（角标刻线/雷达/封印）贯穿首页→use-case→brand 页；4 语言结构零差异

### 不足与改进
**N1｜低｜legacy 页与首页的"卡片语言"仍有细微分叉**
- legacy feature-card 用圆角 radius-md + 实底，现代首页用方角 + hairline + 角标——两种卡片哲学并存
- **改进**：legacy 卡逐步迁移到方角 hairline 体系（不急于全改；新页面一律新体系，旧页面随自然迭代迁移）
- **优先级**：P3（长期方向，非本轮）

**N2｜低｜email 渠道品牌延伸缺失**
- 联系表单确认邮件/通知邮件若为纯文本默认样式，与网站气质断裂
- **改进**：邮件模板复用品牌色块 + 衬线标题 + 角标元素（后端 contact 渠道模板）
- **优先级**：P3
