Core Components

Nine Contracts. One Compliance Stack.

Each module is independently upgradeable via UUPS proxy. Compose only what you need.

01 / CORE

FidesCompliance (V2.1)

Core compliance engine with Guard pre-transaction screening. Extends base compliance with Fides-specific rule evaluation and audit logging.

UUPS Upgradeable Guard Integration Rule Engine
02 / DATA

RiskRegistry

On-chain address risk profile storage. Manages sanctions lists, risk tiers, and CDD labels with role-based access control.

Sanctions List Risk Tiers Role-Based ACL
03 / CONFIG

PolicyEngine

Configurable rules per issuer and wallet. Supports transaction limits, geo-fencing, velocity checks, and multi-sig requirements.

Per-Issuer Rules Tx Limits Geo-Fencing
04 / CHECK

ComplianceEngine

Transaction-level compliance checker. Calls RiskRegistry and PolicyEngine to produce a deterministic pass/fail/quarantine decision.

Deterministic Reentrant-Safe Emergency Pause
05 / GUARD

GuardedComplianceEngine

V2.1 Guard integration layer. Wraps ComplianceEngine with previewTransaction() for pre-flight simulation without state mutation.

V2.1 NEW Pre-Flight Sim Zero State Change
06 / VAULT

QuarantineVault

Isolated fund custody for blocked transactions. Only releasable by authorized reviewers via multi-sig or timelock governance.

Isolated Storage Timelock Release Multi-Sig
07 / TOKEN

CompliantStableCoin

ERC-20 stablecoin with built-in compliance hooks. Every transfer runs through ComplianceEngine before token movement.

ERC-20 HKMA Ready Mint/Burn ACL
08 / WATCH

MempoolWatcher

Off-chain mempool monitor for zero-confirmation risk detection. Feeds real-time risk signals into RiskRegistry via Oracle.

Real-Time Zero-Conf Oracle Feed

Subgraph

The Graph-powered event indexer. Provides GraphQL API for audit reports, transaction history, and compliance dashboards.

How It Works

Step-by-step: what happens when a user clicks "transfer."

01

Transfer Hook Triggered

User calls CompliantStableCoin.transfer(to, amount). The token's overridden transfer function injects a compliance check before any balance changes occur.

02

Guard Pre-Check (V2.1)

Before state mutation, GuardedComplianceEngine.previewTransaction() simulates the full compliance pipeline using staticcall — no gas cost, no state change.

03

Risk & Policy Evaluation

ComplianceEngine.checkTransfer() queries RiskRegistry.getRiskProfile() for both sender and recipient, then evaluates against PolicyEngine rules.

04

Execute or Quarantine

If risk score < threshold: transfer executes normally. If score ≥ threshold: funds are routed to QuarantineVault and a FundsHeld event is emitted.

05

Immutable Audit Trail

Every decision emits a ComplianceCheck event with tx hash, risk score, policy ID, and timestamp. The Subgraph indexes these events for regulator-ready reporting.

Integration Examples

Production-ready snippets for developers.

Guard Pre-Transaction Check

Preview any transaction before execution. Zero gas, zero state change — perfect for wallet UX.

FidesCompliance V2.1
// SPDX-License-Identifier: MIT pragma solidity ^0.8.20; import "@fidesorigin/contracts/FidesCompliance.sol"; contract MyWallet { FidesCompliance public fides; constructor(address _fides) { fides = FidesCompliance(_fides); } // Pre-flight check before any token transfer function safeTransfer( address token, address to, uint256 amount ) external returns (bool) { // Step 1: Guard preview (staticcall, no state change) ComplianceResult memory preview = fides.previewTransaction({ sender: msg.sender, recipient: to, amount: amount, token: token }); // Step 2: If high risk, abort before any state change require(preview.riskLevel < 3, "High risk: transfer blocked"); // Step 3: Execute actual transfer return IERC20(token).transfer(to, amount); } }

Configure Issuer Policy

Set per-issuer rules: daily limits, whitelisted jurisdictions, required KYC tier.

PolicyEngine
// SPDX-License-Identifier: MIT pragma solidity ^0.8.20; import "@fidesorigin/contracts/PolicyEngine.sol"; contract StablecoinIssuer { PolicyEngine public policy; function setupPolicy() external { // Define issuer-wide compliance policy IssuerPolicy memory issuerPolicy = IssuerPolicy({ maxTxAmount: 1_000_000 * 1e6, // $1M USDC per tx dailyLimit: 10_000_000 * 1e6, // $10M daily minKycTier: 2, // Tier 2 KYC required allowedJurisdictions: ["HK", "SG", "US"], requireMultisig: true, autoQuarantine: true // Auto-quarantine on policy breach }); policy.setIssuerPolicy(address(this), issuerPolicy); } // Set per-wallet override (e.g., institutional whitelist) function whitelistInstitution( address wallet, uint256 customLimit ) external onlyOwner { policy.setWalletPolicy(wallet, WalletPolicy({ customTxLimit: customLimit, bypassGeoCheck: true, expiry: block.timestamp + 365 days })); } }
Security

Defense in Depth

Multiple independent safety layers. No single point of failure.

UUPS Proxy Upgrades

OpenZeppelin UUPS pattern with implementation separation. Storage layout validated on every upgrade via @openzeppelin/upgrades-core.

2/3 Gnosis Safe Multi-Sig

All administrative functions require 2-of-3 signatures. No single key can pause, upgrade, or modify risk profiles unilaterally.

Emergency Pause

Guardian role can pause all transfers in <1 block. Paused state emits global event; Subgraph halts new transactions immediately.

48-Hour Timelock

All upgrade and parameter-change transactions are queued for 48 hours before execution. Community can review and react.

Immutable Audit Log

Every ComplianceCheck, FundsHeld, and FundsReleased event is permanently recorded on-chain with tx hash, timestamp, and operator address.

Reentrancy Guard

All state-changing functions use OpenZeppelin ReentrancyGuard. Compliance checks complete before any external calls.
