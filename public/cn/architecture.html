核心组件

九个合约。一套合规栈。

每个模块都可通过 UUPS 代理独立升级。只组合你需要的。

01 / CORE

FidesCompliance (V2.1)

核心合规引擎，具备风控守卫交易前筛查。通过 Fides 特定的规则评估和审计日志扩展基础合规功能。

UUPS 可升级 风控守卫集成 规则引擎
02 / DATA

RiskRegistry

链上地址风险画像存储。通过基于角色的访问控制管理制裁名单、风险层级和 CDD 标签。

制裁名单 风险层级 基于角色的 ACL
03 / CONFIG

PolicyEngine

每个发行方和钱包的可配置规则。支持交易限额、地理围栏、速度检查和多重签名要求。

每发行方规则 交易限额 地理围栏
04 / CHECK

ComplianceEngine

交易级合规检查器。调用 RiskRegistry 和 PolicyEngine 以生成确定性的通过/失败/隔离决策。

确定性 重入安全 紧急暂停
05 / GUARD

GuardedComplianceEngine

V2.1 风控守卫集成层。通过 previewTransaction() 包装 ComplianceEngine，用于飞行前模拟而不改变状态。

V2.1 NEW 飞行前模拟 零状态变更
06 / VAULT

QuarantineVault

被阻止交易的隔离资金托管。仅可通过多重签名或时间锁治理由授权审核员释放。

隔离存储 时间锁释放 多重签名
07 / TOKEN

CompliantStableCoin

内置合规钩子的 ERC-20 稳定币。每次转账在代币转移前都通过 ComplianceEngine 运行。

ERC-20 香港金管局就绪 铸造/销毁 ACL
08 / WATCH

MempoolWatcher

用于零确认风险检测的链下内存池监视器。通过预言机将实时风险信号输入 RiskRegistry。

实时 零确认 预言机推送
09 / INDEX

Subgraph

The Graph 驱动的事件索引器。为审计报告、交易历史和合规仪表板提供 GraphQL API。

GraphQL The Graph 审计 API
深入解析

工作原理

逐步解析：当用户点击"转账"时会发生什么。

01

转账钩子触发

用户调用 CompliantStableCoin.transfer(to, amount)。代币的覆盖转账函数在任何余额变更发生前注入合规检查。

02

风控守卫预检 (V2.1)

在状态变更之前，GuardedComplianceEngine.previewTransaction() 使用 staticcall 模拟完整的合规流水线——无 Gas 成本，无状态变更。

03

风险与策略评估

ComplianceEngine.checkTransfer() 为发送方和接收方查询 RiskRegistry.getRiskProfile()，然后针对 PolicyEngine 规则进行评估。

04

执行或隔离

如果风险分数 < 阈值：转账正常执行。如果分数 ≥ 阈值：资金被路由到 QuarantineVault 并发出 FundsHeld 事件。

05

不可篡改审计追踪

每个决策都会发出带有交易哈希、风险分数、策略 ID 和时间戳的 ComplianceCheck 事件。Subgraph 索引这些事件用于监管就绪报告。

集成示例

面向开发者的生产就绪代码片段。

风控守卫交易前检查

在执行前预览任何交易。零 Gas，零状态变更——完美的钱包 UX。

FidesCompliance V2.1
// SPDX-License-Identifier: MIT pragma solidity ^0.8.20; import "@fidesorigin/contracts/FidesCompliance.sol"; contract MyWallet { FidesCompliance public fides; constructor(address _fides) { fides = FidesCompliance(_fides); } // Pre-flight check before any token transfer function safeTransfer( address token, address to, uint256 amount ) external returns (bool) { // Step 1: Guard preview (staticcall, no state change) ComplianceResult memory preview = fides.previewTransaction({ sender: msg.sender, recipient: to, amount: amount, token: token }); // Step 2: If high risk, abort before any state change require(preview.riskLevel < 3, "High risk: transfer blocked"); // Step 3: Execute actual transfer return IERC20(token).transfer(to, amount); } }

设置每发行方规则：每日限额、白名单司法管辖区、所需 KYC 层级。

PolicyEngine
// SPDX-License-Identifier: MIT pragma solidity ^0.8.20; import "@fidesorigin/contracts/PolicyEngine.sol"; contract StablecoinIssuer { PolicyEngine public policy; function setupPolicy() external { // Define issuer-wide compliance policy IssuerPolicy memory issuerPolicy = IssuerPolicy({ maxTxAmount: 1_000_000 * 1e6, // $1M USDC per tx dailyLimit: 10_000_000 * 1e6, // $10M daily minKycTier: 2, // Tier 2 KYC required allowedJurisdictions: ["HK", "SG", "US"], requireMultisig: true, autoQuarantine: true // Auto-quarantine on policy breach }); policy.setIssuerPolicy(address(this), issuerPolicy); } // Set per-wallet override (e.g., institutional whitelist) function whitelistInstitution( address wallet, uint256 customLimit ) external onlyOwner { policy.setWalletPolicy(wallet, WalletPolicy({ customTxLimit: customLimit, bypassGeoCheck: true, expiry: block.timestamp + 365 days })); } }
安全

纵深防御

多层独立安全层。无单点故障。

UUPS 代理升级

OpenZeppelin UUPS 模式，实现与实现的分离。每次升级通过 @openzeppelin/upgrades-core 验证存储布局。

2/3 Gnosis Safe 多重签名

所有管理功能都需要 3 个签名中的 2 个。没有单个密钥可以单方面暂停、升级或修改风险画像。

紧急暂停

守护者角色可以在 <1 个区块内暂停所有转账。暂停状态发出全局事件；Subgraph 立即停止新交易。

48 小时时间锁

所有升级和参数变更交易在执行前需排队 48 小时。社区可以审查和反应。

不可篡改审计日志

每个 ComplianceCheck、FundsHeld 和 FundsReleased 事件都永久记录在链上，附带交易哈希、时间戳和操作者地址。

重入保护

所有状态变更函数使用 OpenZeppelin ReentrancyGuard。合规检查在任何外部调用之前完成。
