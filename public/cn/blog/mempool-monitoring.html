实时内存池监控实现
零确认风险拦截

FidesOrigin 如何监控内存池，在单笔区块确认之前阻止风险交易——以及为什么传统的事后确认分析为时已晚。

FidesOrigin 工程团队 · 2026年8月 · 10分钟阅读

什么是内存池？

在交易被包含在区块中并提交到区块链之前，它位于一个名为内存池（memory pool）的临时暂存区。每个全节点都维护自己的内存池，一个等待被挖矿的待处理交易动态缓冲区。

当用户广播一笔交易时，它通过对等网络传播并落入数千个节点的内存池中。矿工从他们本地内存池中选择交易以包含在下一个区块中，通常优先选择 gas 费用最高的交易。在区块被挖出之前，该交易是"未确认的"——它存在于网络的意识中，但不在其永久记录中。

这种未确认状态既是特性也是漏洞。它是特性，因为它实现了快速传播和费用市场动态。它是漏洞，因为内存池中的交易仍然可以执行——如果它 destined for 一个受制裁地址、钓鱼合约或已知漏洞，等待区块确认意味着损害已经造成。

零确认问题

传统加密合规遵循简单的工作流程：

  1. 交易广播到网络
  2. 交易被包含在区块中（以太坊上12秒，比特币上约10分钟）
  3. 交易收到1-3次确认
  4. 风险平台针对其数据库查询交易哈希
  5. 合规团队审查警报
  6. 采取行动（如果有）

到第6步时，资金已经转移。合规团队正在记录犯罪，而不是预防犯罪。对于 Base 或 Polygon 等高速链，从广播到最终确定的整个序列可能在3秒以下。人工介入的合规无法跟上。

这就是零确认缺口：交易广播和区块包含之间传统工具是盲目的、人工干预不可能的时间窗口。FidesOrigin 通过将决策点从确认之后移动到包含之前来关闭这一缺口。

关键洞察

在以太坊上，标准 ERC-20 转账在约12秒内确认。但交易在广播后 200-500毫秒 内就在内存池中可见。这200毫秒的窗口就是 FidesOrigin 评估和拦截所需的全部时间。

MempoolWatcher 架构

FidesOrigin MempoolWatcher 是一个实时流管道，通过 WebSocket 连接到全节点，摄取待处理交易，并在它们到达区块之前对照风险注册表进行评估。

1. 全节点 WebSocket 连接

Watcher 通过 WebSocket 与每个支持网络上地理分布的全节点保持持久连接。我们使用带有 newPendingTransactions 主题的 eth_subscribe 来接收交易哈希流，当它们进入内存池时。

WebSocket 订阅 (TypeScript)
// 通过 WebSocket 连接到以太坊全节点 const ws = new WebSocket("wss://eth-mainnet.g.alchemy.com/v2/..."); ws.on("open", () => { ws.send(JSON.stringify({ jsonrpc: "2.0", id: 1, method: "eth_subscribe", params: ["newPendingTransactions"] })); }); ws.on("message", async (data) => { const { params: { result: txHash } } = JSON.parse(data); // txHash 是待处理交易 — 立即评估 await evaluateTransaction(txHash); });

2. 交易解析与解码

每个待处理交易哈希通过 eth_getTransactionByHash 立即获取，以检索完整的交易对象：发送者、接收者、价值、数据载荷和 gas 参数。对于 ERC-20 转账，输入数据被解码以提取实际的代币接收者和转账金额。

// 从输入数据解码 ERC-20 转账 const iface = new ethers.Interface(ERC20_ABI); const decoded = iface.parseTransaction({ data: tx.input }); if (decoded?.name === "transfer") { const [to, amount] = decoded.args; // 'to' 是实际接收者，不一定是 tx.to await screenAddress(to, { sender: tx.from, amount: amount.toString(), token: tx.to, // 代币合约地址 network: "ethereum" }); }

3. 地址匹配与风险评分

一旦提取出发送者和接收者地址，它们就通过两阶段过程对照 FidesOrigin 风险注册表进行检查：

  • 第一阶段 — 精确匹配：地址对照制裁、钓鱼和已知漏洞地址的热名单进行检查。这是 O(1) 哈希映射查找，耗时 <1毫秒。
  • 第二阶段 — 图神经网络评分：对于不在热名单上的地址，图神经网络评估地址的关系图（交易邻居、时间模式、对手风险）。这产生0-100的风险评分。
风险评估管道
async function evaluateTransaction(txHash: string): Promise<RiskResult> { const tx = await provider.getTransaction(txHash); const { from, decodedTo, value } = parseTransaction(tx); // 第一阶段：热名单精确匹配 const hotlistHit = await riskRegistry.isSanctioned(decodedTo); if (hotlistHit) { return { action: "BLOCK", reason: "SANCTIONED_ADDRESS", latencyMs: 12 }; } // 第二阶段：图神经网络关系评分 const score = await gnnModel.scoreAddress(decodedTo, { depth: 2, // 2跳邻域 timeWindow: "24h", minTxCount: 3 }); if (score.value > 85) { return { action: "QUARANTINE", reason: "HIGH_RISK_GNN", score, latencyMs: 67 }; } return { action: "PASS", score, latencyMs: 67 }; }

4. 警报与链上拦截

对于超过风险阈值的交易，存在两条响应路径：

  • 警报模式：交易被标记并通过 Webhook、PagerDuty 或 Slack 发送警报。交易继续进行但记录以供审查。
  • 拦截器模式：对于集成协议（例如 CompliantStablecoin），触发 Guard 模块。如果协议支持预检，交易在智能合约层面被拦截，然后才能执行。

与 Flashbots 的关系

一个常见的问题：内存池监控与 Flashbots 和 MEV（最大可提取价值）有何关系？

Flashbots vs FidesOrigin MempoolWatcher

Flashbots 监控内存池以提取价值——识别套利机会、三明治攻击和清算利润。其目标是经济性的：在他人之前捕获 MEV。

FidesOrigin MempoolWatcher 监控内存池以防止伤害——识别受制裁地址、钓鱼合约和可疑模式。其目标是保护性的：在坏交易确认之前阻止它们。

两者不是竞争对手。事实上，它们是互补的：

  • Flashbots 保护协议经济完整性（无抢跑、公平排序）
  • FidesOrigin 保护协议监管完整性（无制裁地址、合规流程）

Flashbots 的私有内存池（Flashbots Protect）甚至可以增强 FidesOrigin 的有效性：如果协议通过 Flashbots Protect 路由交易，FidesOrigin 仍然可以监控公共交易的内存池，而协议自身的交易则绕过公共 MEV 提取。

以太坊主网上的延迟细分（从 WebSocket 消息接收到风险决策的测量）：

  • 交易获取：25-40毫秒（RPC 往返）
  • 输入解码：1-3毫秒（本地 ABI 解析）
  • 热名单查找：<1毫秒（内存中哈希集）
  • 图神经网络评分：35-55毫秒（缓存嵌入 + 推理）
  • 决策与警报：2-5毫秒
  • 总 p99：97毫秒

在 Base 和 Polygon 等更快的链上，区块时间为2-3秒，100毫秒的评估窗口仅占总确认时间的3-5%，为拦截留下了充足的余量。

局限性与权衡

内存池监控功能强大但并非万能。我们相信透明地讨论其边界：

  • 私有内存池：通过 Flashbots Protect 或私有 RPC（例如 Taichi Network）发送的交易不会出现在公共内存池中。这些需要协议级集成（Guard 模块）而不是内存池监控。
  • 网络传播差异：交易可能先到达某些节点后到达其他节点。Watcher 必须连接到多个地理分布的节点以最小化遗漏率。
  • Replace-by-Fee (RBF)：用户可以用更高费用的版本替换待处理交易，可能更改接收者。Watcher 跟踪交易 nonce 以检测替换。
  • 延迟下限：RPC 往返对延迟施加了物理下限。亚50毫秒端到端需要共置基础设施，这在我们的企业版中可用。

结论

内存池是预执行风险控制的最后前沿。交易在内存池中度过的每一秒都是可以评估、评分——以及如果必要的话——阻止它的一秒。

FidesOrigin 的 MempoolWatcher 关闭了传统事后分析无法解决的零确认缺口。与链上 Guard 模块相结合，它提供两层防御：在内存池中捕获它，如果失败，在合约中阻止它。

对于稳定币发行方、DeFi 协议和任何链上机构来说，这不是锦上添花。这是记录违规的合规与防止违规的合规之间的区别。
