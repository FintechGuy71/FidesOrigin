コアコンポーネント

9つのコントラクト。1つのコンプライアンススタック。

各モジュールは UUPS プロキシを介して独立してアップグレード可能です。必要なものだけを組み合わせてください。

01 / CORE

FidesCompliance (V2.1)

ガードプレトランザクションスクリーニングを備えたコアコンプライアンスエンジン。Fides 固有のルール評価と監査ログでベースコンプライアンスを拡張します。

UUPS アップグレード可能 ガード統合 ルールエンジン
02 / DATA

RiskRegistry

オンチェーンアドレスリスクプロファイルのストレージ。役割ベースのアクセス制御で制裁リスト、リスク層、CDD ラベルを管理します。

制裁リスト リスク層 役割ベース ACL
03 / CONFIG

PolicyEngine

発行者とウォレットごとに設定可能なルール。トランザクション制限、ジオフェンス、速度チェック、マルチシグ要件をサポートします。

発行者ごとのルール Tx 制限 ジオフェンス
04 / CHECK

ComplianceEngine

トランザクションレベルのコンプライアンスチェッカー。RiskRegistry と PolicyEngine を呼び出して、決定論的な通過/不合格/隔離判断を生成します。

決定論的 リエントランシー安全 緊急停止
05 / GUARD

GuardedComplianceEngine

V2.1 ガード統合レイヤー。ComplianceEngine を previewTransaction() でラップし、状態変更なしでのプレフライトシミュレーションを実現します。

V2.1 NEW プレフライトシミュレーション ゼロ状態変更
06 / VAULT

QuarantineVault

ブロックされたトランザクションのための分離資金カストディ。マルチシグまたはタイムロックガバナンスによる承認されたレビュアーのみが解放できます。

分離ストレージ タイムロック解放 マルチシグ
07 / TOKEN

CompliantStableCoin

コンプライアンスフックを内蔵した ERC-20 ステーブルコイン。すべての送金はトークン移動前に ComplianceEngine を通過します。

ERC-20 HKMA 対応 ミント/バーン ACL
08 / WATCH

MempoolWatcher

ゼロコンファメーションリスク検出のためのオフチェーンメンプールモニター。オラクルを介してリアルタイムリスクシグナルを RiskRegistry に供給します。

リアルタイム ゼロコンフ オラクル供給

The Graph 駆動のイベントインデクサー。監査レポート、トランザクション履歴、コンプライアンスダッシュボード用の GraphQL API を提供します。

ディープダイブ

動作原理

ステップバイステップ：ユーザーが「送金」をクリックすると何が起こるか。

01

送金フックがトリガー

ユーザーは CompliantStableCoin.transfer(to, amount) を呼び出します。トークンの上書き送金関数は、残高変更が発生前にコンプライアンスチェックを注入します。

02

ガードプレチェック (V2.1)

状態変更前に、GuardedComplianceEngine.previewTransaction() が staticcall を使用して完全なコンプライアンスパイプラインをシミュレートします——ガスコストなし、状態変更なし。

03

リスクとポリシーの評価

ComplianceEngine.checkTransfer() は送信者と受信者の両方について RiskRegistry.getRiskProfile() を照会し、PolicyEngine ルールに対して評価します。

04

実行または隔離

リスクスコア < しきい値の場合：送金は通常通り実行されます。スコア ≥ しきい値の場合：資金は QuarantineVault にルーティングされ、FundsHeld イベントが発行されます。

05

不変の監査証跡

すべての判断は、トランザクションハッシュ、リスクスコア、ポリシー ID、タイムスタンプを含む ComplianceCheck イベントを発行します。Subgraph はこれらのイベントを規制当局対応レポート用にインデックス化します。

コード

統合例

開発者向けの本番対応コードスニペットです。

ガードプレトランザクションチェック

実行前にあらゆるトランザクションをプレビューします。ゼロガス、ゼロ状態変更——完璧なウォレット UX です。

FidesCompliance V2.1
// SPDX-License-Identifier: MIT pragma solidity ^0.8.20; import "@fidesorigin/contracts/FidesCompliance.sol"; contract MyWallet { FidesCompliance public fides; constructor(address _fides) { fides = FidesCompliance(_fides); } // Pre-flight check before any token transfer function safeTransfer( address token, address to, uint256 amount ) external returns (bool) { // Step 1: Guard preview (staticcall, no state change) ComplianceResult memory preview = fides.previewTransaction({ sender: msg.sender, recipient: to, amount: amount, token: token }); // Step 2: If high risk, abort before any state change require(preview.riskLevel < 3, "High risk: transfer blocked"); // Step 3: Execute actual transfer return IERC20(token).transfer(to, amount); }

発行者ポリシーの設定

発行者ごとのルールを設定します：日次制限、ホワイトリスト法域、必要な KYC 層。

PolicyEngine
// SPDX-License-Identifier: MIT pragma solidity ^0.8.20; import "@fidesorigin/contracts/PolicyEngine.sol"; contract StablecoinIssuer { PolicyEngine public policy; function setupPolicy() external { // Define issuer-wide compliance policy IssuerPolicy memory issuerPolicy = IssuerPolicy({ maxTxAmount: 1_000_000 * 1e6, // $1M USDC per tx dailyLimit: 10_000_000 * 1e6, // $10M daily minKycTier: 2, // Tier 2 KYC required allowedJurisdictions: ["HK", "SG", "US"], requireMultisig: true, autoQuarantine: true // Auto-quarantine on policy breach }); policy.setIssuerPolicy(address(this), issuerPolicy); } // Set per-wallet override (e.g., institutional whitelist) function whitelistInstitution( address wallet, uint256 customLimit ) external onlyOwner { policy.setWalletPolicy(wallet, WalletPolicy({ customTxLimit: customLimit, bypassGeoCheck: true, expiry: block.timestamp + 365 days })); }
セキュリティ

ディフェンス・イン・デプス

複数の独立した安全層。単一障害点はありません。

UUPS プロキシアップグレード

OpenZeppelin UUPS パターンによる実装の分離。すべてのアップグレードで @openzeppelin/upgrades-core によるストレージレイアウトの検証。

2/3 Gnosis Safe マルチシグ

すべての管理機能には 3 つの署名のうち 2 つが必要です。単一のキーが一方的に一時停止、アップグレード、リスクプロファイルの変更を行うことはできません。

緊急停止

ガーディアンロールは 1 ブロック未満ですべての送金を一時停止できます。一時停止状態はグローバルイベントを発行し、Subgraph は新規トランザクションを即座に停止します。

48 時間タイムロック

すべてのアップグレードとパラメータ変更トランザクションは、実行前に 48 時間キューに入ります。コミュニティがレビューし対応できます。

不変の監査ログ

すべての ComplianceCheck、FundsHeld、および FundsReleased イベントは、トランザクションハッシュ、タイムスタンプ、およびオペレーターアドレスと共にオンチェーンに永続的に記録されます。

リエントランシーガード

すべての状態変更関数は OpenZeppelin ReentrancyGuard を使用します。コンプライアンスチェックはすべての外部呼び出しの前に完了します。
