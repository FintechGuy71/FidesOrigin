メンプールとは何か？

取引がブロックに含まれてブロックチェーンにコミットされる前に、一時的な待機エリアであるメンプール（メモリープール）に滞留します。すべてのフルノードは独自のメンプールを維持しており、マイニングを待つ保留中の取引の動的バッファです。

ユーザーが取引をブロードキャストすると、ピアツーピアネットワークを伝播し、数千のノードのメンプールに到達します。マイナーはローカルメンプールから次のブロックに含める取引を選択し、通常はガス手数料が最も高いものを優先します。そのブロックがマイニングされるまで、取引は「未確認」です。

この未確認状態は特性であり、同時に脆弱性でもあります。しかし、メンプール内の取引はまだ実行可能です——制裁対象アドレス、フィッシングコントラクト、または既知のエクスプロイトを対象とする場合、ブロックコンファメーションを待つことは損害が既に生じていることを意味します。

ゼロコンファメーション問題

従来の暗号通貨コンプライアンスは、シンプルなワークフローに従います：取引ブロードキャスト → ブロック含む → コンファメーション → リスククエリ → アラート → 対応。ステップ6までには、資金は既に移動しています。コンプライアンスチームは犯罪を記録しており、予防しているわけではありません。

これがゼロコンファメーションギャップです。FidesOriginは、判断ポイントをコンファメーション後からインクルージョン前に移動することで、このギャップを解消します。

重要な洞察

Ethereumでは、標準的なERC-20転送は約12秒でコンファームされます。しかし、取引はブロードキャストから200-500ミリ秒以内にメンプールで可視になります。この200ミリ秒のウィンドウが、FidesOriginが評価とインターセプトに必要なすべてです。

MempoolWatcherアーキテクチャ

FidesOrigin MempoolWatcherは、フルノードへのWebSocket接続を介してリアルタイムストリーミングパイプラインを構築し、保留中の取引を取り込み、ブロックに到達する前にリスクレジストリに対して評価します。

1. フルノードWebSocket接続

Watcherは、各サポートネットワーク上の地理的に分散したフルノードへの永続的なWebSocket接続を維持します。eth_subscribeにnewPendingTransactionsトピックを使用して、メンプールに入る取引ハッシュのストリームを受信します。

WebSocket Subscription (TypeScript)
// Connect to Ethereum full node via WebSocket const ws = new WebSocket("wss://eth-mainnet.g.alchemy.com/v2/..."); ws.on("open", () => { ws.send(JSON.stringify({ jsonrpc: "2.0", id: 1, method: "eth_subscribe", params: ["newPendingTransactions"] })); }); ws.on("message", async (data) => { const { params: { result: txHash } } = JSON.parse(data); await evaluateTransaction(txHash); });

2. 取引解析とデコーディング

各保留中の取引ハッシュは、eth_getTransactionByHashを介して即座に取得され、完全な取引オブジェクトを取得します。ERC-20転送の場合、入力データがデコードされて、実際のトークン受信者と転送額が抽出されます。

3. アドレスマッチングとリスクスコアリング

送信者と受信者アドレスが抽出されたら、FidesOriginリスクレジストリに対して2段階のプロセスでチェックされます：

  • フェーズ1——正確なマッチング：アドレスは、制裁対象、フィッシング、および既知のエクスプロイトアドレスのホットリストに対してチェックされます。これはO(1)のハッシュマップルックアップで、1ミリ秒未満です。
  • フェーズ2——GNNスコアリング：ホットリストにないアドレスの場合、グラフニューラルネットワークがアドレスの関係グラフを評価します。これにより0-100のリスクスコアが生成されます。

4. アラートとオンチェーンインターセプト

リスク閾値を超えた取引には、2つの応答パスが存在します：アラートモード（取引にフラグが立てられ、アラートが送信される）とインターセプターモード（スマートコントラクトレベルで取引がブロックされる）。

Flashbotsとの関係

Flashbotsはメンプールを監視して価値を抽出します——裁定機会、サンドイッチ攻撃、および清算利益を識別します。FidesOrigin MempoolWatcherはメンプールを監視して害を防ぎます——制裁対象アドレス、フィッシングコントラクト、および怪しいパターンを識別します。両者は競合ではなく、補完的です。

パフォーマンスベンチマーク

  • エンドツーエンドレイテンシ：<100ミリ秒
  • 誤検出率：<0.1%（1000万+取引で検証済み）
  • カバレッジネットワーク：6+（Ethereum、Base、Polygon、Arbitrum、Optimism、BSC）

Ethereumメインネットでの総P99レイテンシは97ミリ秒です。

限界とトレードオフ

  • プライベートメンプール：Flashbots ProtectやプライベートRPC経由の取引はパブリックメンプールに表示されません。これらにはプロトコルレベルの統合（ガードモジュール）が必要です。
  • ネットワーク伝播の分散：Watcherは複数の地理的に分散したノードに接続する必要があります。
  • Replace-by-Fee（RBF）：Watcherはトランザクションノンスを追跡して置き換えを検出します。
  • レイテンシの下限：RPC往復はレイテンシに物理的な下限を課します。サブ50ミリ秒には共置インフラが必要です。

結論

メンプールは、実行前リスクコントロールの最後のフロンティアです。FidesOriginのMempoolWatcherは、従来の事後分析では対処できないゼロコンファメーションギャップを解消します。オンチェーンガードモジュールと組み合わせることで、2層の防御を提供します：メンプールで捕捉し、それが失敗した場合はコントラクトで阻止します。
