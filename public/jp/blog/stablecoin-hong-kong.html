香港ライセンス要件と技術実装

FidesOriginが香港金融管理局のステーブルコインライセンス要件を満たすための技術ガイド。準備監査から償還コントロールまで、すべてオンチェーンで実装。

香港金融管理局ステーブルコインフレームワーク

2024年12月、香港金融管理局（HKMA）は、待望のステーブルコイン規制フレームワークを発表し、香港で運営する、または香港居住者を対象とするステーブルコイン発行者のためのライセンス制度を確立しました。このフレームワークは、世界的に最も包括的なものの一つであり、準備管理、償還権、AML/CFTコンプライアンス、および公衆開示を網羅しています。

発行者にとっての課題は、ルールを理解することだけではありません——それらを、規制要件とブロックチェーンテクノロジーの制約の両方を満たす方法で実装することです。この記事では、FidesOriginがHKMAの各要件を具体的なオンチェーン実装にどのようにマッピングするかを説明します。

香港金融管理局の主要要件一覧

香港金融管理局のフレームワーク（2024年12月の協議結論で概説）は、ライセンスを受けたステーブルコイン発行者に以下を要求します：（1）ステーブルコイン価値を完全に裏付ける準備の維持；（2）1営業日以内の額面償還；（3）堅牢なAML/CFTコントロールの実装；（4）所定の開示；（5）継続的な監督と監査の受け入れ。

香港金融管理局コンプライアンスの4つの柱

香港金融管理局の要件は、4つの柱にグループ化できます。各柱には規制意図と技術実装パスがあります。

準備資産

高品質流動性資産による全額裏付け。分離保管。毎日の評価。公開認証。

償還権

T+1以内の額面償還。恣意的な制限なし。償還リクエストに対する自動コンプライアンスチェック。

AML / CFT

リアルタイムトランザクションモニタリング。アドレススクリーニング。疑わしい活動報告。Travel Ruleコンプライアンス。

開示

完全な条項を含むホワイトペーパー。準備構成レポート。監査結果。リアルタイムの供給量と準備データ。

柱1：準備資産管理

規制意図：流通中のすべてのステーブルコインは、分離保管された高品質流動性資産により1:1で裏付けられている必要があります。準備は検証可能、監査可能であり、発行者の破産から保護されている必要があります。

FidesOriginの実装：FidesOriginは準備を保持しません（これは発行者の財務機能です）が、準備状況を透明かつ監査可能にするオンチェーンインフラストラクチャを提供します。

オンチェーン準備認証

発行者の財務ウォレット（マルチシグGnosis Safe）は準備資産を保持します。FidesOriginのSubgraphは、財務ウォレットの残高とステーブルコイン総供給量をインデックス化し、リアルタイムで裏付け比率を計算します：

Subgraph: Reserve Backing Ratio (GraphQL)
# Real-time reserve backing query query ReserveStatus { treasurySnapshot(orderBy: timestamp, orderDirection: desc, first: 1) { reserveAssetsUSD stablecoinSupply backingRatio timestamp custodianAttestationHash } # Returns: { backingRatio: 1.0012, reserveAssetsUSD: "1001200000", ... }

custodianAttestationHashは、保管銀行が毎日公開するMerkleルートで、オフチェーン準備報告書にコミットします。誰でも、発行者の言葉を信頼することなく、オンチェーン供給量が認証された準備と一致することを検証できます。

緊急停止と準備回復

裏付け比率が1.0未満になった場合（過少担保を示す）、FidesOriginのポリシーエンジンは自動的に以下をトリガーできます：

  • 鋳造停止：新しいステーブルコインの発行は、準備が回復するまで停止されます
  • 償還優先：償還は他のすべての転送より先に処理されます
  • アラートエスカレーション：発行者の財務およびコンプライアンスチームへのマルチチャネルアラート

柱2：償還権

規制意図：ステーブルコインホルダーは、1営業日以内にそのトークンを基礎となる法定通貨価値に交換でき、恣意的な制限や差別的な条項なしに行う必要があります。

FidesOriginの実装：償還フローは、コンプライアンスチェックをスマートコントラクトに直接埋め込み、償還リクエストが自動的に処理される一方でAMLコントロールが維持されることを保証します。

FidesOriginを使用した償還フロー

1
ユーザーがdAppまたはAPIを介して償還リクエストを開始
↓
2
ガードプリチェック：KYCステータス、制裁スクリーニング、速度制限
↓
3a
合格：ステーブルコインが焼却され、法定通貨が財務から解放され、TXハッシュが記録される
↓
3b
不合格：償還がブロックされ、ユーザーに通知され、コンプライアンスアラートが生成され、監査ログが書き込まれる

償還フローの重要な設計上の決定：

  • ノンカストディアルKYC：KYCステータスは、プライバシーが必要な場合にゼロ知識証明で検証可能なオンチェーン証明として保存されます。集中型データベースではありません。発行者は個人データを開示することなくKYCが確認されたことを証明できます。
  • 速度制限：ポリシーエンジンは、1アドレスあたりの日次/時間ごとの償還制限を強制し、突然の銀行擠兌や構造化償還によるマネーロンダリングを防ぎます。
  • 監査ログ：すべての償還試行（成功または失敗）は、オフチェーンの法定通貨転送レコードにマッピングされる一意のコンプライアンス参照IDとともにオンチェーンに記録されます。

柱3：AML / CFTコントロール

規制意図：顧客デューデリジェンス、トランザクションモニタリング、制裁スクリーニング、および疑わしい活動報告を含む包括的なAML/CFTプログラムを実装します。

FidesOriginの実装：これは、FidesOriginのコアアーキテクチャが最大の価値を提供する領域です。プロトコルは3層のAML保護を提供します：

レイヤー1：アドレススクリーニング（取引前）

すべての取引は、実行前にリスクレジストリに対してスクリーニングされます。レジストリには以下が含まれます：

  • OFAC SDNリスト（OFAC公開後1時間以内に更新）
  • FATF高リスク管轄区域
  • ChainalysisおよびEllipticが特定した高リスクアドレス
  • 内部発行者ブラックリスト（例：既知の詐欺に関連するアドレス）

レイヤー2：トランザクションモニタリング（継続的）

取引前スクリーニングと取引後分析の間に、FidesOriginはSubgraphを介してリアルタイムトランザクションモニタリングを提供します：

  • パターン検出：構造化（大金額を小額取引に分割）、複数のアドレスを介した迅速な移動、ミキサーとの相互作用パターン
  • 閾値アラート：設定可能な閾値を超える取引に対する自動アラート
  • クロスチェーントラッキング：秘匿化の試みを特定するためのブリッジ転送の監視

レイヤー3：疑わしい活動報告

システムが疑わしい活動を検出すると、構造化されたSAR（疑わしい活動報告）ペイロードが生成され、発行者のコンプライアンスチームがレビューし、香港の共同財務情報局（JFIU）に提出できます：

SAR Payload Generation
{ "reportId": "SAR-2026-08-06-0042", "triggerType": "STRUCTURING_PATTERN", "subjectAddress": "0x742d...3e8D9", "totalAmountUSD": 450000, "transactionCount": 47, "timeWindow": "24h", "riskIndicators": [ { "type": "MIXER_INTERACTION", "confidence": 0.94 }, { "type": "VELOCITY_ANOMALY", "confidence": 0.89 } ], "onChainEvidence": "ipfs://QmXyZ...", "complianceReference": "FIO-HK-20260806-0042" }

柱4：開示と透明性

規制意図：ステーブルコインホルダーと規制機関は、ステーブルコインの条項、準備状況、および監査結果に関する正確かつタイムリーな情報にアクセスできる必要があります。

FidesOriginの実装：Subgraphはリアルタイム開示エンジンとして機能し、すべてのコンプライアンス関連データへのプログラマティックアクセスを提供します。

エンドツーエンドコンプライアンスフロー

以上をすべて組み合わせると、FidesOriginを使用する香港ライセンス取得ステーブルコインの3つの主要な運用フローは以下の通りです：

発行フロー

1
ユーザーが発行者のオンボーディングポータルでKYCを完了
↓
2
KYC証明書がオンチェーン証明として鋳造される
↓
3
ユーザーが発行者の預託口座に法定通貨を入金
↓
4
預託者が入金を確認 → ポリシーエンジンが鋳造を承認 → ステーブルコインがユーザーウォレットに鋳造される

転送フロー

1
ユーザーが受信者アドレスに転送を開始
↓
2
ガードプリチェック：KYCステータス、制裁リスト、速度制限、GNNリスクスコア
↓
3a
合格：転送が実行され、コンプライアンスイベントが記録される
3b
不合格：取引が理由とともにリバートされ、アラートが生成される

償還フロー

1
ユーザーがdAppを介して償還をリクエスト
↓
2
ガードが検証：KYC有効、制裁なし、速度制限内
↓
3a
合格：ステーブルコインが焼却され、法定通貨転送が開始され、コンプライアンスログが書き込まれる
3b
不合格：リクエストが拒否され、ユーザーに通知され、必要に応じてSARが生成される

実世界の展開

香港を拠点とするステーブルコイン発行者（機密保護のため名前は非公開）は、2025年第2四半期にFidesOriginを統合し、その後香港金融管理局のライセンス申請について原則的承認を受けました。主な成果：

展開成果

監査効率：香港金融管理局の監査人は、Subgraphにクエリすることですべてのコンプライアンス判断を独立して検証でき、監査プロセスを推定6週間から10日間に短縮しました。

自動レポート：香港金融管理局への月次コンプライアンスレポートは、Subgraphデータから自動生成されるようになり、手動のスプレッドシート作成を排除しました。

ゼロ偽陰性：8か月の運用中、システムは制裁対象アドレスを含む取引の100%を正しく識別およびブロックしました（OFAC更新に対するテストで検証済み）。

規制信頼：FidesOriginのコントラクトのオープンソースで監査可能な性質により、香港金融管理局の監査人は、コンプライアンスロジックが発行者によって秘密裏に変更されないという確信を持つことができました。

結論

香港のステーブルコインフレームワークは、規制機関がブロックチェーンテクノロジーと建設的にどのように関わることができるかのモデルです。要件は明確であり、基準は高く、コンプライアンスへの道は技術的に実行可能です。

FidesOriginは、このコンプライアンスアーキテクチャを現実のものとするインフラストラクチャ層を提供します。準備認証からリアルタイムAMLスクリーニング、不変の監査証跡まで、すべての香港金融管理局の要件は、具体的なオンチェーン実装にマッピングされます。

ステーブルコイン発行者にとって、選択はコンプライアンスするかどうかではありません——規制の方向性は明確です。選択はどのようにコンプライアンスするかです：不透明性とベンダーロックインをもたらすクローズドソースのSaaSツールを使用するか、透明性、監査可能性、および規制信頼を提供するオープンソースのオンチェーンインフラストラクチャを使用するか。

私たちはFidesOriginを後者のために構築しました。
