核心元件

九個合約。一套合規堆疊。

每個模組都可透過 UUPS 代理獨立升級。只組合你需要的。

01 / CORE

FidesCompliance (V2.1)

核心合規引擎，具備風控守衛交易前篩查。透過 Fides 特定的規則評估和審計日誌擴展基礎合規功能。

UUPS 可升級 風控守衛整合 規則引擎
02 / DATA

RiskRegistry

鏈上地址風險畫像儲存。透過基於角色的存取控制管理制裁名單、風險層級和 CDD 標籤。

制裁名單 風險層級 基於角色的 ACL
03 / CONFIG

PolicyEngine

每個發行方和錢包的可配置規則。支援交易限額、地理圍欄、速度檢查和多重簽名要求。

每發行方規則 交易限額 地理圍欄
04 / CHECK

ComplianceEngine

交易級合規檢查器。呼叫 RiskRegistry 和 PolicyEngine 以生成確定性的通過/失敗/隔離決策。

確定性 重入安全 緊急暫停
05 / GUARD

GuardedComplianceEngine

V2.1 風控守衛整合層。透過 previewTransaction() 包裝 ComplianceEngine，用於飛行前模擬而不改變狀態。

V2.1 NEW 飛行前模擬 零狀態變更
06 / VAULT

QuarantineVault

被阻止交易的隔離資金託管。僅可透過多重簽名或時間鎖治理由授權審核員釋放。

隔離儲存 時間鎖釋放 多重簽名
07 / TOKEN

CompliantStableCoin

內建合規鉤子的 ERC-20 穩定幣。每次轉帳在代幣轉移前都通過 ComplianceEngine 執行。

ERC-20 香港金管局就緒 鑄造/銷毀 ACL
08 / WATCH

MempoolWatcher

用於零確認風險檢測的鏈下記憶體池監視器。透過預言機將即時風險訊號輸入 RiskRegistry。

即時 零確認 預言機推送
09 / INDEX

Subgraph

The Graph 驅動的事件索引器。為審計報告、交易歷史和合規儀表板提供 GraphQL API。

GraphQL The Graph 審計 API
深入解析

工作原理

逐步解析：當使用者點擊"轉帳"時會發生什麼。

01

轉帳鉤子觸發

使用者呼叫 CompliantStableCoin.transfer(to, amount)。代幣的覆蓋轉帳函數在任何餘額變更發生前注入合規檢查。

02

風控守衛預檢 (V2.1)

在狀態變更之前，GuardedComplianceEngine.previewTransaction() 使用 staticcall 模擬完整的合規流水線——無 Gas 成本，無狀態變更。

03

風險與策略評估

ComplianceEngine.checkTransfer() 為發送方和接收方查詢 RiskRegistry.getRiskProfile()，然後針對 PolicyEngine 規則進行評估。

04

執行或隔離

如果風險分數 < 閾值：轉帳正常執行。如果分數 ≥ 閾值：資金被路由到 QuarantineVault 並發出 FundsHeld 事件。

05

不可竄改審計追蹤

每個決策都會發出帶有交易雜湊、風險分數、策略 ID 和時間戳的 ComplianceCheck 事件。Subgraph 索引這些事件用於監管就緒報告。

風控守衛交易前檢查

在執行前預覽任何交易。零 Gas，零狀態變更——完美的錢包 UX。

FidesCompliance V2.1
// SPDX-License-Identifier: MIT pragma solidity ^0.8.20; import "@fidesorigin/contracts/FidesCompliance.sol"; contract MyWallet { FidesCompliance public fides; constructor(address _fides) { fides = FidesCompliance(_fides); } // Pre-flight check before any token transfer function safeTransfer( address token, address to, uint256 amount ) external returns (bool) { // Step 1: Guard preview (staticcall, no state change) ComplianceResult memory preview = fides.previewTransaction({ sender: msg.sender, recipient: to, amount: amount, token: token }); // Step 2: If high risk, abort before any state change require(preview.riskLevel < 3, "High risk: transfer blocked"); // Step 3: Execute actual transfer return IERC20(token).transfer(to, amount); } }

設定每發行方規則：每日限額、白名單法域、所需 KYC 層級。

// SPDX-License-Identifier: MIT pragma solidity ^0.8.20; import "@fidesorigin/contracts/PolicyEngine.sol"; contract StablecoinIssuer { PolicyEngine public policy; function setupPolicy() external { // Define issuer-wide compliance policy IssuerPolicy memory issuerPolicy = IssuerPolicy({ maxTxAmount: 1_000_000 * 1e6, // $1M USDC per tx dailyLimit: 10_000_000 * 1e6, // $10M daily minKycTier: 2, // Tier 2 KYC required allowedJurisdictions: ["HK", "SG", "US"], requireMultisig: true, autoQuarantine: true // Auto-quarantine on policy breach }); policy.setIssuerPolicy(address(this), issuerPolicy); } // Set per-wallet override (e.g., institutional whitelist) function whitelistInstitution( address wallet, uint256 customLimit ) external onlyOwner { policy.setWalletPolicy(wallet, WalletPolicy({ customTxLimit: customLimit, bypassGeoCheck: true, expiry: block.timestamp + 365 days })); } }
安全

縱深防禦

多層獨立安全層。無單點故障。

UUPS 代理升級

OpenZeppelin UUPS 模式，實現與實現的分離。每次升級透過 @openzeppelin/upgrades-core 驗證儲存布局。

2/3 Gnosis Safe 多重簽名

所有管理功能都需要 3 個簽名中的 2 個。沒有單個密鑰可以單方面暫停、升級或修改風險畫像。

緊急暫停

守護者角色可以在 <1 個區塊內暫停所有轉帳。暫停狀態發出全域事件；Subgraph 立即停止新交易。

48 小時時間鎖

所有升級和參數變更交易在執行前需排隊 48 小時。社群可以審查和反應。

不可竄改審計日誌

每個 ComplianceCheck、FundsHeld 和 FundsReleased 事件都永久記錄在鏈上，附帶交易雜湊、時間戳和操作者地址。

重入保護

所有狀態變更函數使用 OpenZeppelin ReentrancyGuard。合規檢查在任何外部呼叫之前完成。
