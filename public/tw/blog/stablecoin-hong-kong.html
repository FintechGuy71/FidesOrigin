香港金管局穩定幣框架

2024年12月，香港金融管理局（HKMA）發布了期待已久的穩定幣監管框架，為在港營運或面向香港居民的穩定幣發行方建立了牌照制度。該框架是全球最全面的之一，涵蓋儲備管理、贖回權、反洗錢/反恐怖融資（AML/CFT）合規以及公眾揭露。

對於發行方而言，挑戰不在於理解規則——更在於以同時滿足監管要求和區塊鏈技術約束的方式實施這些規則。本文闡釋FidesOrigin如何將HKMA的每項要求映射到具體的鏈上實現。

香港金管局核心要求一覽

香港金管局框架（如2024年12月諮詢總結所述）要求持牌穩定幣發行方：（1）維持完全支持穩定幣價值的儲備；（2）在一個工作日內按面值贖回；（3）實施穩健的AML/CFT控制；（4）進行規定揭露；（5）接受持續監督和審計。

香港金管局合規四大支柱

香港金管局的要求可分為四大支柱。每根支柱既有監管意圖，也有技術實現路徑。

儲備資產

以高品質流動性資產全額支持。隔離託管。每日估值。公開認證。

贖回權

T+1內按面值贖回。無任意限制。對贖回請求自動執行合規檢查。

反洗錢/反恐融資

即時交易監控。地址篩查。可疑活動報告。Travel Rule合規。

資訊揭露

含完整條款的白皮書。儲備構成報告。審計結果。即時供應量和儲備資料。

支柱一：儲備資產管理

監管意圖：每枚流通中的穩定幣必須以1:1比例由高品質流動性資產支持，存放在隔離託管中。儲備必須可驗證、可審計，並受保護免於發行方破產。

FidesOrigin實現：雖然FidesOrigin不持有儲備（這是發行方的財資職能），但它提供鏈上基礎設施，使儲備狀態透明且可審計。

鏈上儲備認證

發行方的財資錢包（多簽Gnosis Safe）持有儲備資產。FidesOrigin的Subgraph索引財資錢包餘額和穩定幣總供應量，即時計算支持比例：

Subgraph: Reserve Backing Ratio (GraphQL)
# Real-time reserve backing query query ReserveStatus { treasurySnapshot(orderBy: timestamp, orderDirection: desc, first: 1) { reserveAssetsUSD stablecoinSupply backingRatio timestamp custodianAttestationHash } # Returns: { backingRatio: 1.0012, reserveAssetsUSD: "1001200000", ... }

custodianAttestationHash是託管銀行每日發布的Merkle根，承諾鏈下儲備報表。任何人都可以驗證鏈上供應量與認證儲備是否匹配，無需信任發行方的陳述。

緊急暫停與儲備恢復

如果支持比例低於1.0（表明抵押不足），FidesOrigin的策略引擎可以自動觸發：

  • 暫停鑄造：新穩定幣發行暫停，直至儲備恢復
  • 贖回優先：贖回在其他轉帳之前處理
  • 警報升級：向發行方財資和合規團隊發送多渠道警報

支柱二：贖回權

監管意圖：穩定幣持有者必須能夠在一個工作日內將其代幣兌換為底層法幣價值，不受任意限制或歧視性條款約束。

FidesOrigin實現：贖回流程將合規檢查直接嵌入智能合約，確保贖回請求自動處理，同時保持AML控制。

贖回流程的關鍵設計決策：

  • 非託管式KYC：KYC狀態以鏈上憑證形式儲存（在需要隱私時可透過零知識證明驗證），而非集中式資料庫。發行方可以證明已進行KYC審核，同時不洩露個人資料。
  • 速率限制：策略引擎強制執行每地址每日/每小時的贖回限額，防止突然的銀行擠兌或透過結構化贖回進行洗錢。
  • 審計日誌：每次贖回嘗試（成功或失敗）都在鏈上記錄，附帶唯一合規參考ID，映射到鏈下法幣轉帳記錄。

支柱三：反洗錢/反恐融資控制

監管意圖：實施全面的AML/CFT計畫，包括客戶盡職調查、交易監控、制裁篩查和可疑活動報告。

FidesOrigin實現：這是FidesOrigin核心架構發揮最大價值的領域。該協議提供三層AML保護：

第一層：地址篩查（交易前）

每筆交易在執行前都透過風險註冊表進行篩查。註冊表包括：

  • OFAC SDN名單（OFAC發布後1小時內更新）
  • FATF高風險管轄區
  • Chainalysis和Elliptic識別的高風險地址
  • 內部發行方黑名單（例如與已知詐欺關聯的地址）
Transfer with AML Screening (Solidity)
function _beforeTokenTransfer(address from, address to, uint256 amount) internal override { // Check sender and recipient against Risk Registry require(!riskRegistry.isSanctioned(from), "Sender sanctioned"); require(!riskRegistry.isSanctioned(to), "Recipient sanctioned"); // Velocity check: max $100K per address per day require( dailyVolume[from] + amount <= 100_000e18, "Daily limit exceeded" ); // GNN risk scoring for non-hotlist addresses uint8 riskScore = riskRegistry.getRiskScore(to); require(riskScore < 85, "High-risk recipient"); }

第二層：交易監控（持續）

在交易前篩查和交易後分析之間，FidesOrigin透過Subgraph提供即時交易監控：

  • 模式檢測：結構化拆分（將大額拆分為小額交易）、透過多個地址快速轉移、混幣器交互模式
  • 閾值警報：超過可配置閾值的交易自動生成警報
  • 跨鏈追蹤：監控跨鏈橋轉帳以識別混淆企圖

第三層：可疑活動報告

當系統檢測到可疑活動時，會生成結構化SAR（可疑活動報告）載荷，供發行方合規團隊審查並提交給香港聯合財富情報組（JFIU）：

支柱四：資訊揭露與透明度

監管意圖：穩定幣持有者和監管機構必須能夠獲取關於穩定幣條款、儲備狀態和審計結果的準確、及時資訊。

FidesOrigin實現：Subgraph充當即時揭露引擎，提供對所有合規相關資料的程序化存取。

Subgraph作為揭露API

FidesOrigin使發行方不再發布靜態PDF報告，而是提供即時資料流，監管機構、審計師和資深使用者可以直接查詢：

部署成果

審計效率：香港金管局審查員能夠透過查詢Subgraph獨立驗證所有合規決策，將審計流程從預估的6週縮短至10天。

監管信心：FidesOrigin合約的開源、可審計性質讓香港金管局審查員確信合規邏輯不會被發行方秘密修改。

結論

香港的穩定幣框架是監管機構如何建設性地與區塊鏈技術互動的典範。要求明確、標準高、合規路徑在技術上是可行的。

FidesOrigin提供了使這一合規架構成真的基礎設施層。從儲備認證到即時AML篩查，再到不可篡改的審計追蹤，每項香港金管局要求都映射到具體的鏈上實現。

對於穩定幣發行方而言，選擇不在於是否合規——監管方向已明確。選擇在於如何合規：是使用造成不透明和供應商鎖定的閉源SaaS工具，還是使用提供透明度、可審計性和監管信心的開源鏈上基礎設施。

我們建構FidesOrigin是為了後者。
